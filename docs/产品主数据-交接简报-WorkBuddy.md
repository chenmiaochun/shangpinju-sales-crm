## 一、目标

把现有系统的"商品"从**一行一个**升级为**多级产品主数据体系**，产品库成为全系统中心（销售/库存/采购/售后/经营分析都引用它）。核心要求：

1. **组件库 → 手工精选单品 → 套餐**，不自动铺开所有规格组合
2. **权限分层**：员工只看到成品（单品/套餐：名称/售价/可用库存/上下架）；店长/采购/财务才能看组件价格、成本、库存
3. 产品资料含**完整电子手册**（多图、详情卖点、尺寸图、材质图、颜色图、安装保养说明、质检标准、产品手册附件、适用空间/风格/系列、展示排序）
4. **新老并存**：老商品继续用现有开单/库存/采购逻辑，不破坏现有功能

## 二、业务层级（6 层）

```
大类 ProductCategory → 主件 ProductComponent（每个主件有自己的规格维度）
→ 最小单位 SkuUnit（挂价格/成本/库存）→ 单品 ConfigProduct（老板手工精选组合）
→ 套餐 ProductPackage（单品组合，可配置数量）
```

- 每个主件的**规格维度可以不一样**（餐台面 2 维、餐台脚 3 维）
- 底层"最小单位"才真正挂价格/成本/库存，上面全是组合层
- 不同品类**主件数可不同**（餐椅 1 个主件、沙发 5 个主件、床 4 个主件），系统统一以最小单位为底
- 每个单品有**结构类型**：一体（1 主件，如抱枕/床垫）/ 组合（多主件，如五福沙发）

### 全屋实木定制（已确认思路）
- **定制产品定型化**：不是自由设计，而是**复用上面各品类的主件/最小单位**，加"可定制"标记，尺寸可按客户量尺**自由输入**（其他规格照常从列表选）。
- **归法**：复用现有品类主件（如定制衣柜用"衣柜类"主件），不另建一套体系。
- **定制计价**：按「主件价格 × 尺寸比例」计算（比例 = 定制尺寸 ÷ 基准尺寸）；**不同品类/主件可用不同公式**（尺寸比例 / 面积 / 延米 / 固定），公式可配置。
- **木材**：多个品种可选（材质规格维度）。
- 定制订单：按单生产，不锁现货库存（走现有生产需求流程）。

## 四、核心业务规则（已定死，必须遵守）

1. **不自动生成全组合**：单品由老板手工精选创建，系统绝不自动铺开所有规格组合。
2. **价格公式**：
   - 单品标准价 = Σ(主件价格 × 数量) + 增减价（可正/负/0）
   - 套餐价 = Σ(单品标准价 × 数量) + 套餐增减价
   - 开单时仍可手工改单价/给折扣。
3. **编码系统自动生成**：主件短码(如 餐台面=CTM)；SKU=主件码-规格码(如 CTM-1.8M-HZW)；单品=SP-大类码-序号；套餐=TC-序号。原则：唯一、可读、可扩展。
4. **库存挂最小单位**：开单选单品→按模板自动展开成最小单位明细→各扣对应库存；含「定制生产」主件→不扣库存、转生产需求单；保留直接开最小单位配件单。
5. **组合规则简单化**：约束写进单品模板（每个主件「锁定某规格值」或「开放某几个规格值」），不建复杂规则表。
6. **权限分层**：员工只看到成品总价；组件成本/增减价对员工不可见；开单选规格但只显示成品总价。
7. **新老并存**：老商品(ProductCatalogItem)保留，现有开单/库存/采购/InventoryPage 不重构。
8. **异构结构支持**：不同品类主件数可不同。
9. **订单明细详情单**：订单/报价要能生成"明细详情单"给客户——尤其全屋定制，展开到每个组件（几个抽屉、几块层板、各多少钱），让客户清晰、送货不差错；实现上复用"开单自动展开成最小单位明细"（Phase 3）。

## 五、数据结构（Phase 1 要建的 8 类类型）

`ProductCategory`(大类) / `ProductComponent`(主件+`ComponentSpecDim`规格维度) / `SkuUnit`(最小单位) / `ConfigProduct`(单品+`ConfigProductComponent`模板) / `ProductPackage`(套餐+`PackageItem`) / `MediaFile`+`ProductMedia`(媒体资料)

关键字段：
- `SkuUnit`: sku(自动编码)、specValues、unitPrice、costPrice、supplyType(现货/展厅样品/外采/定制生产)、availableStock、reservedStock、safetyStock、supplier、image、status
- `ConfigProduct`: name、code、description、style、series、applicableSpace、sortOrder、media、components[锁定/开放规格]、adjustPrice、status
- `ProductMedia`: images多图、dimensionImages尺寸图、materialImages材质图、colorImages颜色图、installationDoc安装说明、careDoc保养、manualFiles手册附件、qualityStandard质检标准

## 六、技术约束（已核实，必须遵守）

1. **数据双端存储**：前端从 `GET /api/state` 加载，变更走 `PUT /api/state` 全量状态存到服务端 SQLite `app_state` 表（单行 id=1）；浏览器 localStorage(key=`shangpinju.customer-followup.v1`) 只是缓存，**服务端是最终数据源**。
2. 新增集合必须同时处理 4 条路径：
   - `RemoteSalesState`（`src/api/salesApi.ts`）加入新集合
   - `SalesState`/`loadState`（`src/store/SalesDataContext.tsx`）缺省 `[]`（老数据兼容）
   - `server/database.mjs` 的 `CONCURRENT_RECORD_KEYS` 加入新集合（按记录并发合并）
   - 备份/恢复、`PUT /api/state` 校验回归验证
3. **媒体/附件走服务端 uploads 上传，存 URL 不存 base64**（避免 app_state 单行 JSON 暴涨）。
4. **无需新增数据库表**（状态是整体 JSON 存在 app_state 单行）。
5. 保留 `ProductCatalogItem`、现有页面、现有开单/库存/采购逻辑。

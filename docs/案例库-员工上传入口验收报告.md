- **需求来源**：老板 2026-08-31 口头需求——「给员工一个上传图片和案例的入口，上传后更新到数据库和销售系统」

## 一、功能说明

新增「案例库」模块（导航菜单 / 路由 `/cases`），所有登录员工（销售/设计/运营等，`tasks.own` 权限）均可使用。

### 员工视角
1. 点导航「案例库」→ 右上「上传图片 / 案例」
2. 填：标题（必填）、分类（成交案例/客户实拍/安装现场/空间搭配/其他）、客户（建议脱敏）、关联产品（输入框有产品库自动联想）、备注
3. 选多张图片（自动上传，单张 ≤20MB，第一张为封面）
4. 提交 → 立即入库（sales.sqlite `cases` 表）→ 全员刷新可见

### 数据与权限
| 操作 | 谁可以 |
|---|---|
| 看列表 / 看图 | 所有登录员工（已隐藏的仅店长可见） |
| 上传案例 | 所有登录员工 |
| 修改 / 删除 | 店长 或 案例上传者本人 |
| 隐藏 / 恢复展示 | 仅店长 |

- 图片文件存 `server/data/uploads/`（复用既有 `/api/files` 通道，有每日自动备份覆盖）
- 服务端严格校验：标题必填 ≤80 字、备注 ≤2000 字、图 ≤30 张、关联产品 ≤10 个
- 所有写操作进审计日志（audit_log）

## 二、技术实现

- **后端**：`server/database.mjs` 新增 cases 表 + 4 个方法；`server/app.mjs` 新增 4 条 REST 路由（仿「记一笔」ideas 模式）
- **前端**：`src/features/cases/`（CaseLibraryPage + cases.css），复用产品主数据的 MediaUploader 组件；`salesApi.ts` 加 4 个方法（静态演示模式降级 localStorage）
- **上线方式**：3001 服务重启由 service-guard 守护进程自动完成（杀进程→30 秒内重拉），cases 表建表迁移随启动自动执行；前端 vite 热更新即时生效

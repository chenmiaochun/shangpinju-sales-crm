## 第 0 章 系统与访问总览

「尚品居经营系统」把**客户、开单、产品、案例、库存、售后、经营分析** 集中在一个系统里。系统的"大脑"跑在**店长这台电脑** 上，员工用手机或电脑连上店里 WiFi 即可使用。

### 0.1 三种打开方式

方式 A 浏览器（最通用）：连店里 WiFi → 浏览器输入 `http://192.168.1.161:5173` → 收藏。手机可"添加到主屏幕"。**不要用微信内打开** ，用系统浏览器。

方式 B 桌面客户端（推荐电脑办公员工）：连店里 WiFi，电脑打开 `http://192.168.1.161:3001/download` → 点「下载安装包」（约 106MB）→ 双击 `尚品居经营系统-安装版-1.0.0.exe` 一路下一步 → 桌面出图标 → 双击登录。 _客户端只是壳，需店长电脑开着且连 WiFi。_

方式 C 手机网页：同方式 A，已适配手机屏。

### 0.2 登录

  * 每个员工有独立账号（密码问店长）。**店长默认** ：`admin` ／ `spj6688`（建议尽快改，见第 16 章）。
  * 首次登录后系统提示改密码：右上角头像 → **修改密码** 。
  * 忘记密码：找店长在「团队权限」重置。



### 0.3 界面总览

区域| 位置| 作用  
---|---|---  
左侧导航| 最左边竖排| 按角色显示可用模块（线索、客户、开单、订单、产品、案例、任务、分析、设置等）  
顶部搜索| 顶部中间| 搜客户姓名 / 手机号 / 车牌 / 订单号 / 产品名，回车跳转对应页面  
顶部铃铛| 右上角| 逾期跟进、今日待跟进、设计任务、交付任务等提醒聚合  
账号菜单| 右上角头像| 系统设置、成员与权限、数据管理、修改密码、退出登录  
记一笔| 右下角浮动按钮| 随时提需求 / 报问题（见第 17 章）  
  
> 不同账号看到的菜单不同——员工只看到自己权限内的功能，看不到店长专属模块（如经营分析、团队权限、数据管理），这是正常的权限隔离。

## 第 1 章 线索数据（/leads）

**谁能看：** 销售、运营（有客户相关权限的员工）。**作用：** 登记和跟进新客来源，再转为正式客户。

### 1.1 新建线索

点「新建线索」，填写：

字段| 必填| 说明  
---|---|---  
姓名| 是| 客户称呼  
手机号| 是| 用于后续跟进与搜索  
意向产品| 否| 如沙发、衣柜等  
户型 / 预算 / 装修进度| 否| 帮助判断成交概率  
来源| 否| 如门店自然客流、小红书、老客介绍  
备注| 否| 自由记录  
负责人| 否| 可指派给当前登录销售或运营  
  
### 1.2 操作

  1. 1新建线索后，在列表里点该线索可看详情。
  2. 2**分配负责人** ：把线索派给对应销售跟进。
  3. 3**导入** ：支持 CSV 批量导入（按页面模板整理列）。
  4. 4**转为客户** ：确认要跟进成单时，把线索转成「客户跟进」里的正式客户，进入完整客户生命周期。



> 线索是"还没成交的潜在客"。转成客户后，后续跟进、开单都在「客户跟进」里进行。

## 第 2 章 客户跟进（/customers）

**谁能看：** 有客户权限的员工（自己的客户；店长看全部）。**作用：** 管理客户档案、跟进记录、推进成交。

### 2.1 列表筛选

顶部可按：阶段、负责人、意向（高/中/低）、跟进状态（全部 / 待跟进 / 已逾期）、搜索框、仅看临时录入，筛选客户。

### 2.2 客户详情区块

区块| 能做什么  
---|---  
客户画像| 基本信息总览  
跟进时间线| 查看历史跟进记录  
新增跟进| 写本次跟进内容、选结果（如已量房 / 已报价 / 待决策），可补充备注  
客户档案编辑| 改预算、意向产品、风格、装修进度、户型、顾虑、备注  
登记成交| 标记客户成交 → 自动生成一张「已签约」订单与供应需求  
设计协助需求| 向设计岗发起协助  
客户交接| 把客户从一个销售交接给另一个（handoff / 接收）  
  
### 2.3 日常操作步骤

  1. 在列表点客户进入详情。
  2. 每次沟通后点**新增跟进** ，选结果、写内容 → 保存，时间线自动追加。
  3. 客户确定购买，点**登记成交** ，系统生成订单骨架，后续到「销售开单 / 订单管理」完善。
  4. 离职或换人负责，用**客户交接** 转交，避免客户流失。



## 第 3 章 销售开单（/orders）

**谁能看：** 销售、店长。**作用：** 开销售单、算价、收定金、推进订单生效。

### 3.1 开单页三个区块

  * **选客户 / 商品** ：选当前客户（无客户会提示先建临时客户）、搜索并加入商品。
  * **订单明细（购物车）** ：每行可改规格、材质、单位、数量、单价、备注；可上传报价文件。
  * **定金与实收价** ：见 3.3。



### 3.2 商品选择来源（三个标签页）

标签| 内容  
---|---  
产品库单品| 已上架的配置单品，按"品类 → 系列"三级折叠树浏览，可选规格自动算价；缺数据时可"添加临时产品"  
产品库套餐| 已配置套餐，含多件单品，选配后算价  
商品库| 只读展示的老商品库（product catalog）  
  
### 3.3 价格与定金字段

字段| 说明  
---|---  
其他费用| 运费、上楼费等附加  
实收价| 客户讲价后的最终价；默认等于订单总价，可改；有"跟随总价"一键还原  
定金比例（%）| 填比例，金额自动算；与"定金金额"双向联动  
定金金额（可改）| 直接填具体金额（如 9000 / 10000），比例会自动反算；客户最终定金与默认 50% 不一致时改这里  
整单备注| 楼层、入户、送货、安装等约定  
  
### 3.4 保存与订单流水线

点**保存销售单** ：生成订单并提示"在预览中打印并完成签名留存"。订单进入**订单处理** 区，按状态推进：

当前状态| 可点按钮| 含义  
---|---|---  
草稿| 提交客户确认| 发给客户看  
待客户确认| 客户已确认| 客户确认后转待审核  
已签名已确认| 提交店长审核| 送店长审  
待审核| 登记定金 / 审核并生效| 定金够则点"审核并生效"，自动生成库存 / 采购 / 工厂需求  
  
> ⚠️ **已知问题（已发现，待修复）：** 当前"保存销售单"会把订单存入 `待客户签名` 状态，但流水线上没有这个状态的推进按钮，订单会卡住只能"查看/打印"。临时对策：店长在「订单管理」里手动调整，或等修复后用"草稿"状态开单。小吉已在缺陷清单中记录，建议优先修复。

另外：**登记定金** 弹窗可收一笔定金（微信等），收足后"审核并生效"才可用。

## 第 4 章 订单管理（/lifecycle）

**谁能看：** 销售、店长。**作用：** 看全部订单进度、收款、退换货、交付、关联售后。

  * **收款明细** ：查看每笔收款（定金、进度款等）。
  * **取消订单** ：终止订单。
  * **退货 / 换货** ：对单品执行退或换。
  * **交付任务** ：新增 / 更新送货交付任务，跟踪是否送达。
  * **售后关联** ：把订单关联到售后单。
  * **供应需求** ：查看该订单产生的采购 / 工厂需求。



## 第 5 章 售后管理（/after-sales）

**谁能看：** 有客户权限的员工。**作用：** 登记和处理售后问题。

  1. 列表可按：全部 / 待处理 / 已解决 筛选。
  2. **新建售后单** ：选客户、关联订单、填问题、指派负责人。
  3. 处理完点**更新状态** （待处理 → 已解决）。



## 第 6 章 产品目录（/products）

**谁能看：** 全员（给客户展示用）。**作用：** 只读浏览产品库图文资料。

  * 按品类 / 系列查看产品卡片。
  * 点开看大图、规格、材质、价格区间等，方便面对客户讲解。
  * 这是"展示层"，要改产品资料请到「产品主数据」（第 8 章，限库管 / 店长）。



## 第 7 章 案例库（/cases）

**谁能看 / 传：** 全员可见、全员可传；修改 / 删除限上传者本人或店长。**作用：** 沉淀实景案例图，给客户参考。

### 7.1 上传案例

  1. 点**上传图片 / 案例** 展开表单，填写：

字段| 必填| 说明  
---|---|---  
标题| 是| 案例名称  
分类| 是| 成交案例 / 客户实拍 / 安装现场 / 空间搭配 / 其他  
客户| 否| 可填（敏感信息建议脱敏）  
关联产品| 否| 逗号分隔的产品名  
备注| 否| 风格、小区等  
图片| 是| 可多张，第一张作封面  
  
  2. 点**提交案例** ，卡片出现在网格里。



### 7.2 查看与管理

  * 顶部搜索框按标题 / 产品 / 客户 / 上传人搜；分类 chips 快速筛选。
  * 卡片上可**隐藏 / 显示** （下架但不删）、**删除** （限本人或店长）。
  * 点图片进入查看器看大图。



## 第 8 章 产品主数据（/product-master）

**谁能看：** 库管 / 店长（`inventory.manage`）。**作用：** 维护产品基础资料，是「产品目录 / 开单」的数据源。

页面分多个标签页：

标签| 作用  
---|---  
品类组件| 维护品类与组件  
配置单品| 上架 / 下架配置好的单品，设定价格与可选规格  
组件成本| 维护组件成本（影响毛利，受 `cost.view` 控制可见性）  
套餐| 组合多个单品成套餐  
库存台账| 查看库存流水台账  
导入| 用 Excel 批量导入产品资料  
媒体| 上传商品图  
  
> 开单时选不到产品，多半是这里没上架或系列没配齐——先到本页确认单品已上架、规格已配置。

## 第 9 章 商品进销存（/inventory）

**谁能看：** 库管 / 店长。**作用：** 管库存、出入库、调拨、盘点、补仓。

页面区块：产品列表、供应需求、库存流水、仓库、仓库存量、库存单据、补仓申请。可操作（按权限）：

  * **新增产品** 、**库存调整** （盘盈盘亏修正）。
  * **出入库 / 调拨 / 盘点** ：生成库存单据。
  * **补仓申请与审批** ：库存不足时发起，店长审批。
  * 细粒度权限：收货、发货、调拨、盘点、采购、补仓申请 / 审批、成本查看分别可单独开关。



## 第 10 章 任务中心（/tasks）

**谁能看：** 全员。**作用：** 聚合待办，分销售任务（跟进）与设计任务（接收 / 提交成果 / 审核 / 退回）两类，可切 `?mode=design` 看设计视角、交付任务。

## 第 11 章 经营分析（/dashboard）

**谁能看：** 店长（`store.analytics`）。**作用：** 客户漏斗、成交 / 收款、产品、设计产能等数据看板，辅助经营决策。

## 第 12 章 AI 工具（质检 / 沟通分析 / 深度洞察）

**谁能看：** 店长相关权限。**作用：** 纯前端分析，输入来自系统内的客户 / 跟进 / 订单数据：

  * **沟通分析** ：分析沟通记录。
  * **深度洞察** ：综合数据挖掘经营洞察。
  * 部分分析可"应用"写回客户或补一条跟进。



## 第 13 章 销售 SOP / 辅导中心

**谁能看：** 管理岗相关权限。**作用：** 销售标准流程（SOP）话术与新人辅导资料，统一团队打法。

## 第 14 章 团队权限（/team）

**谁能看：** 店长（`members.manage`）。**作用：** 管理员工账号、角色与权限。

操作| 按钮| 说明  
---|---|---  
新增员工账号| 新增员工账号| 建账号，默认密码由系统生成（6 位数字）  
编辑权限| 编辑 / 保存权限| 在权限矩阵里勾选该账号能做什么  
启用 / 停用| 启停开关| 离职员工及时停用，保留记录  
重置密码| 重置密码| 员工忘密码时，重置为 6 位数字（告知员工）

## 第 15 章 数据管理（/data-admin）

**谁能看：** 数据管理员（`data.manage`）。**作用：** 备份、恢复、接入配置、收款设置。

  * **健康卡** ：看客户数、缺失手机号、孤立跟进等数据质量。
  * **本地备份** ：点下载备份，在前端用当前数据生成 JSON 下载保存。
  * **恢复** ：选备份文件 → 校验 → 准备恢复 → 确认恢复（恢复业务数据子集）。
  * **企业微信接入** ：保存接入配置（密钥等）。
  * **收款设置** ：配置收款相关参数。



> 系统还有每日 21:30 自动备份（存在服务器 `backups/` 目录，留 7 天）。重要数据建议店长定期额外下载一份备份留存。

## 第 16 章 账号与密码

### 16.1 修改自己的密码

  1. 右上角点头像 → **修改密码** 。
  2. 填：当前密码、新密码（6 位数字 或 10 位以上字符）、确认新密码。
  3. 点确认。规则：新密码不能与旧密码相同。



> ⚠️ **已知问题（已发现，待修复）：** 当前改完密码后本设备会被意外登出（应保留本设备登录、只踢其他设备）。临时对策：改完重新登录一次即可。小吉已记录，建议尽快修复。

### 16.2 退出登录

右上角头像 → **退出登录** 。

### 16.3 店长改 admin 初始密码（强烈建议）

用 `admin / spj6688` 登录 → 修改密码 → 改成强密码。改完让小吉删掉工作区里的明文密码脚本。

## 第 17 章 记一笔 / 全局搜索

### 17.1 记一笔（右下角浮动按钮）

任何页面右下角都有「记一笔」。用来提需求、报问题、记灵感。

  1. 点按钮 → 写内容（≤1000 字）→ 选模块（订单报价 / 产品主数据 / 客户线索 / 库存 / 经营分析 / 售后 / 系统其它 / 待分类）。
  2. 提交。店长能在「记一笔 · 全部」里看所有人提的内容并改状态（待评估 / 已排期 / 开发中 / 已上线 / 不做）。



> 写得越具体越好。例："开单选客户要翻很久，希望按手机号搜" 比 "不好用" 有用得多。

### 17.2 全局搜索（顶部）

顶部搜索框输入客户姓名 / 手机号 / 车牌 / 订单号 / 产品名，回车跳转对应页面。当前为前端即时过滤，数据量很大时会变慢（后续可优化）。

## 第 18 章 日常维护、更新说明、排错

### 18.1 日常维护（店长必看）

  1. **服务器 = 店长电脑** ，营业时间尽量别关机 / 断网，否则全员打不开。
  2. 已设**开机自启 + 崩溃自愈** ，一般不用手动管。
  3. 每天 **21:30 自动备份** ，存 `backups/`，留 7 天。
  4. IP 固定为 `192.168.1.161`；建议路由器 MAC 绑定双保险。
  5. **切勿** 在服务运行时用别的工具直接改 `sales.sqlite` 数据库文件（会搞成只读、全员登录失败）。



### 18.2 更新说明

系统本质是网页，桌面客户端只是"打开网页的壳"。后期加功能 / 修 bug **只改网址那边的代码，员工不用重下 exe** 。只有改了桌面壳子本身才需重打包。更新生效前提：店长电脑开着、连 WiFi；想看最新内容关掉重开客户端 / 刷新网页。

### 18.3 打不开怎么办（三步）

  1. WiFi 连的是店里的吗？
  2. 店长电脑开了吗？
  3. 地址对吗？（`192.168.1.161:5173`）



桌面客户端打不开会跳"离线引导页"，IP 变了就在那填新地址 → 测试连接 → 保存并重新连接。还不行联系小吉。

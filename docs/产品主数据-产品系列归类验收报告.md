## 二、关键设计

1. **公共/其他 = 虚拟系列**：用常量 `PUBLIC_SERIES_ID` 表示，不写入数据库。好处：
   - 历史数据零迁移：`seriesId` 空 = 公共/其他；
   - 删除真实系列时，其下主件自动迁回公共/其他（不会丢主件）；
   - 不产生"幽灵记录"，数据干净。
2. **系列仅做分组视图**：`ProductSeries { id, categoryId, name, sort, builtin? }` 不参与任何价格/库存/编码计算。
3. **数据链路四端同步**：types → SalesDataContext → RemoteSalesState → 服务端 `CONCURRENT_RECORD_KEYS` 均已加 `series` 集合，多端并发写不丢系列。
4. **新增数据操作**：`moveComponentsToSeries(componentIds, seriesId)`，传 `undefined` 即迁回公共/其他。

## 五、界面验收操作路径（请老板自测）

打开 `localhost:5173` → 左侧「产品主数据」→「品类与主件」：

1. **建系列**：选中一个大类（如沙发类）→ 第二栏「+ 新增系列」→ 建「五福系列」「尚品系列」等；
2. **看内置系列**：第二栏第一条永远有「公共/其他」，无删除按钮；历史主件全在这里；
3. **新增主件**：第三栏「+ 新增主件」→ 弹窗第一项即【归属产品系列】，不选无法保存；
4. **批量迁移**：点「批量迁移」→ 勾选多个主件 → 底部选目标系列 → 确认迁移；
5. **联动验证**：切到「单品配置」→ 主件下拉按系列分组折叠；「组件与成本」→ 列表带系列标签、可按系列筛选；
6. **导入验证**（可选）：「批量导入」→ 模板里「系列」列填系列名 → 预览会显示"新建系列"数。

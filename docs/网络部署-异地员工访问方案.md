## 一、背景

老板（Angel）要求：让其他员工可以使用本系统，但员工与服务器**不在同一局域网**（跨网/异地）。
服务器即老板本机（Windows，内网 IP `192.168.1.17`，2026-08-30 从 `192.168.110.x` 换到 `192.168.1.x` 网段），系统平时通过 `localhost:5173` 内嵌浏览器使用。

## 二、方案选型结论

| 方案 | 结论 | 原因 |
|------|------|------|
| Tailscale | ❌ 放弃 | 当前网络环境下 `login.tailscale.com` / `controlplane.tailscale.com` 直连与经代理均被阻断，无法注册登录 |
| **ZeroTier 虚拟局域网** | ✅ 采用 | `my.zerotier.com` / `download.zerotier.com` 国内直连畅通；P2P 直连性能好；免费额度 25 用户 / 50 网络足够 |
| 云服务器部署 | 暂不考虑 | 有月租成本且需迁移数据，现阶段不必要 |

## 三、本次服务器端已完成的改动

1. **Vite 监听所有网卡**
   `vite.config.ts` 与 `vite.config.js` 增加：
   ```js
   server: { host: true, port: 5173, strictPort: true,
     proxy: { '/api': { target: 'http://127.0.0.1:3001', changeOrigin: true } } }
   ```
   > 关键点：前端 API 地址逻辑只在 `localhost` 打开时才走 3001，外部设备用 IP 打开页面时 API 会指向 5173 自身。增加 `/api` 代理后此问题解决，**外部只需访问 5173 一个端口**。
   > 注意：`vite.config.js` 是 tsc 编译产物，Vite 优先加载它，两个文件必须同步修改。

## 四、后续步骤（需要老板操作 + 小吉配合）

1. 老板到 **my.zerotier.com** 注册/登录账号（国内可直连；若用 Google/GitHub 登录需走代理）
2. Create A Network → 得到 **16 位 Network ID**
3. 把 Network ID 告诉小吉，或自己右下角 ZeroTier 图标 → Join Network 填入
4. 在 my.zerotier.com 网络页面 **Authorize** 节点 `360c2e39a0`
5. 建议：网络设置里 IPv4 选 `Easy`（自动分配 172.x.x.x 网段），并把网络可见性设为 Private

## 五、员工接入方式（发给员工的说明）

1. 电脑/手机安装 ZeroTier（官网 download.zerotier.com，国内可直连下载）
2. 加入老板提供的网络 ID（Join Network）
3. 等老板在网页上授权（Auth 复选框打勾）
4. 浏览器访问：`http://<服务器虚拟IP>:5173`（虚拟 IP 在 my.zerotier.com 网络页可查）
5. 用各自的账号密码登录系统（账号由老板在系统「团队成员」里创建）

## 六、注意事项

- **老板电脑 = 服务器**，关机/睡眠则全员无法访问，建议关闭睡眠、保持开机
- 启动方式不变：`npm run dev`（`node scripts/dev.mjs`），改动不影响本机 `localhost:5173` 使用习惯
- 数据安全：服务端仍是最终数据源（SQLite `app_state`），多端并发写入按记录合并，逻辑未动
- 后续若用户数增多或需要公网稳定域名，可升级云服务器部署，届时只需迁移 `server/data`

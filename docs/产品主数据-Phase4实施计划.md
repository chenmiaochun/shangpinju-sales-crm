## 一、范围与目标

实施方案对 Phase 4 的定义：

1. 套餐在开单/报价中使用（数量选项如 餐椅 4/6）
2. 采购 / 售后 / 经营分析 接入产品库
3. 老数据迁移工具 + 产品库 Excel 批量导入 + 产品图片接入
4. **验收口径：产品库成为全员资料入口，角色权限生效**

代码盘点（2026-08-26）发现 **3 个 Phase 3 遗留断层**，属于「采购/售后接入」的实质内容，也是真实使用会立即踩到的正确性问题：

| # | 断层 | 位置 | 后果 |
|---|---|---|---|
| A | 订单取消不释放 SKU 预留 | `SalesDataContext.tsx` cancelOrder（982-1031 行）：只释放老商品 `products/warehouseStocks`，未处理 `demand.skuUnitId` | 生效后取消订单，`SkuUnit.reservedStock` 永久虚高、可用量虚低，只能手动台账调 |
| B | 采购到货不入 SKU 库存 | `updateSupplyDemand` 到货分支（1514-1558 行）：按 `orderItem.productId` 找老商品，单品行无此字段 → 提前 return | 单品行的外采需求到货验收后，SKU 台账库存不涨、无 InventoryMovement 流水 |
| C | 退货只支持老商品 | `returnOrderItem`（1052 行起）：按 `item.productId` 找 product，找不到整单跳过 | 单品行退货无法入 SKU 库存；换货同理 |

**因此本计划把断层修复排在第一步，正确性优先于新功能。**

## 二、总体原则（延续前三阶段，不变）

- **新老并存**：老商品（`ProductCatalogItem`）的开单/库存/采购/售后路径一行不动；新能力全部走可选字段扩展。
- **服务端零改动为目标**：`orders / supplyDemands / skuUnits / inventoryMovements` 均已在 `CONCURRENT_RECORD_KEYS`，新字段随记录 JSON 自然合并与备份。Phase 4 各步均**不新增顶层集合**（若某步需要，会在该步单独标注 4 条路径改动）。
- **权限**：组件层价格/成本对员工不可见（UI `cost.view` 门控 + 快照数据不落成本价）。成品层价格（单品价、套餐价）员工可见。
- **每步过四道闸**：`tsc` 0 错 / `vitest` 全过 / `vite build` / 服务端 20 项回归；每步完成后老板可界面验收，全部完成出 Phase 4 总验收报告。

## 三、分步计划（共 7 步）

### 4.1 SKU 库存闭环：取消释放 + 到货入库【断层 A+B 修复 · 中 · 建议最先】

**目标**：单品订单的库存生命周期完整闭环——生效锁定 → 取消释放 → 采购到货入库 + 流水。

**改动**：
| 文件 | 内容 |
|---|---|
| `src/store/SalesDataContext.tsx` | ① `cancelOrder`：对 `skuUnitId` 需求同步释放 `skuUnits.reservedStock`（与老商品同语义，Math.max(0,…) 防负数）；② `updateSupplyDemand` 到货分支加 skuUnitId 路径：`availableStock += receivedDelta`、`reservedStock += receivedDelta`（到货即为客户预留，与老商品到货语义一致），找不到 SKU（如纯定制无对应 SKU）时只完成需求不动库存 |
| `src/types.ts` | `InventoryMovement` 加可选 `skuUnitId?/sku?`（老流水零迁移） |
| `src/utils/order-fulfillment.ts` | 无需改（生成侧已正确） |

**验收口径**：开单品单（现货）→ 生效 → 台账预留 +1 → 取消 → 预留归零可用恢复；外采单品单 → 建采购 → 到货验收合格 N → SKU 库存 +N、预留 +N、库存流水出现「采购入库」记录。

**风险**：改动集中在 `cancelOrder/updateSupplyDemand` 两个既有函数，需补两类单测防回归（取消释放、到货入库），老商品路径必须原样。

---

### 4.2 套餐开单【中 · 官方范围第 1 项】

**目标**：开单页可选套餐 → 逐单品选配（数量选项/可选勾选/规格）→ 自动带价 → 生效按最小单位展开扣减。类型、价格函数（`packagePrice` 已预留 `picks` 参数）、配置页（PackageTab）均已就绪，**缺的全是消费侧**。

**关键设计**：
- `OrderItem` 加可选 `packageId?/packageCode?/packageItems?: PackageOrderItem[]`，其中 `PackageOrderItem = { productId, productCode, productName, quantity, selections, skuLines }`——**`skuLines` 平铺到订单行顶层**（供生效展开），`packageItems` 仅用于打印分组展示。这样 `planSkuDemands` 完全不用改（数量 = 单套用量 × 单品数量 × 套餐套数，在构建快照时乘好）。
- 开单页来源变三个 Tab：产品库单品 / **产品库套餐** / 商品库。套餐卡片显示价格区间（`packagePriceRange`）+ 含 N 件单品 + 可售状态（各单品聚合）。
- 新增 `PackagePicker.tsx` 对话框：每个单品一张卡（optional 勾选、数量按 `quantityOptions` 单选或默认值、逐主件规格选择——复用 `componentSkuOptions`），实时 `packagePrice`。
- **权限**：员工可见套餐价与各单品成品价小计（成品层），不可见组件单价/增减价（组件层），与规则 2.6 一致。
- `OrderPreviewModal` 组件明细区块支持套餐行：套餐头 + 按单品分组小表 + 套餐组合价行。

**验收口径**：「餐厅套系 = 餐桌×1 + 餐椅×4/6 + 餐边柜×1(可选)」→ 选餐椅 6、勾掉餐边柜 → 套餐价 = Σ单品价×数量 + 套餐增减价 → 生效后椅身等 SKU 预留按 6 套锁定；员工端只见套餐合计与单品小计。

**风险**：低——完全复用 Phase 3 的快照/展开/门控模式，无服务端改动。

### 4.3 报价单打印模式【小 · 简报规则 9 补全】

**目标**：报价也能出「明细详情单」（订单侧 Phase 3 已有，报价侧缺失）。

**推荐方案 A（轻量）**：现状草稿订单即报价（开单流程条「2 保存报价草稿」），给 `OrderPreviewModal` 加**打印样式切换**：
- 报价单样式：抬头「产品报价单」、报价日期 + 有效期（`SalesOrder` 加可选 `quoteValidUntil?`）、不出定金/签名区，明细含单品/套餐组件明细（复用现有区块）；
- 销售单样式：现状不动。

**备选方案 B（重，不推荐本期做）**：独立 Quote 实体（新集合 + 4 条路径 + 报价→订单转化流程）。仅当老板真有「一客多版报价、报价版本管理」需求时才值得。**需老板拍板。**

**验收口径**：草稿订单 → 打印预览 → 切「报价单」样式 → 出含组件明细的报价单；生效后打印仍是销售单样式。

### 4.4 售后接入【中 · 断层 C 修复 + 工单结构化】

**目标**：售后全链路支持产品库单品/套餐行。

**改动**：
1. `returnOrderItem` / `exchangeOrderItem` 支持带 `skuLines` 的行：退货 → SKU `availableStock` 回加、对应预留释放（如有）；换货 → 新选择重新生成需求（复用 `planSkuDemands` 思路）。
2. `AfterSalesTicket` 加可选结构化商品引用（`configProductId?/packageId?/orderItemId?`），与现有 `productInfo` 文本并存（老工单零迁移）；工单详情可显示单品/套餐/组件层级。
3. （可选，默认做）补件类工单一键生成对应 SKU 的补货需求单。

**验收口径**：单品订单退货 → SKU 库存回加、台账可见；售后工单从该订单创建 → 工单里能看到是哪个单品的哪些组件；补件工单生成补货需求。

**风险**：退货/换货涉及库存与需求双向操作，是 Phase 4 改动逻辑最重的一步，单测要覆盖足额/不足额/部分退场景。

### 4.5 产品目录页 + 产品图片接入【中 · Phase 4 验收标准的核心】

**目标**：「产品库成为全员资料入口」——目前媒体（多图/尺寸图/材质图/颜色图/安装保养/手册/质检标准）上传后**全系统没有任何展示页**，产品库唯一消费入口是开单页。

**改动**：
- 新路由 `/products` 产品目录页（全员可见，登录即可）：上架单品 + 套餐卡片流（主图、名称、编码、系列/风格、成品价、可售状态），筛选（品类/风格/系列/关键词），点开详情抽屉：媒体画廊（多图/尺寸图/材质图/颜色图）+ 安装保养/手册附件下载 + 质检标准 + 适用空间。成本一律不出现。
- 开单页单品/套餐卡片加主图缩略图（`media.images[0]`）。
- 报价单/销售单打印可选带单品主图（小图，老板确认要再加，默认先不做）。

**验收口径**：员工账号登录 → 左侧导航出现「产品目录」→ 浏览单品/套餐图文资料 → 全程看不到成本；老板看到同样内容。

**风险**：低——纯只读新页面，不动任何既有集合。

### 4.6 经营分析接入【中】

**目标**：现在两个分析页（`SalesInsightsPage`/`ManagerDashboard`）**都不读 orders 集合**，「产品热度」是客户意向而非成交。接入真实订单数据。

**改动**（SalesInsightsPage 加「商品分析」区块，或独立 Tab）：
- **商品销售分析**：按订单行聚合——单品（configProductId）/ 套餐（packageId）/ 老商品（productId）三路归一，销量、销售额、排名、趋势；
- **品类分析**：单品→大类聚合，各品类销售额占比；
- **毛利分析**（`cost.view` 门控，员工不可见）：分析时实时 join `skuUnitId → SkuUnit.costPrice`（老商品用 product.costPrice）算 售价-成本/毛利率；快照仍不落成本价，数据层安全不破；
- 无 SKU 成本数据的行标记「无成本数据」不猜。

**验收口径**：老板看商品销售排名 + 品类占比 + 毛利率；员工/无 cost.view 账号看不到毛利区块。

**风险**：低——纯只读分析；注意毛利区块双重门控（页面权限 + cost.view）。

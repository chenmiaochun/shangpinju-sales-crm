# 销售订单定金金额可编辑 验收报告

- **日期**：2026-09-01
- **commit**：见 git log
- **需求来源**：老板 2026-09-01 截图反馈——销售开单时默认 50% 算出的定金（如 9600）常与客户最终付款金额（9000 / 10000）不符，原 UI 只能改"定金比例"，得不到 46.875% 这种尴尬数字

## 一、功能改动

销售开单页（`/orders`）右侧购物车底部：

**之前**：仅一个「定金比例 %」输入框，应收定金按 `实收价 × 比例` 自动算出、只读
**之后**：并列两个输入框：
- 「定金比例 %」（自动反推，可手改）
- 「定金金额 ¥」（**销售直接输入最终客户要付的数**）

两者双向同步：
- 改比例 → 金额自动算
- 改金额 → 比例自动算（保留 2 位小数）
- 改实收价 → 金额按"销售最后设定的比例"重算（保持比例作为销售偏好的锚）

## 二、保存字段

- `requiredDeposit`（应收定金）= `depositAmount`（销售定的金额）
- `depositRate`（定金比例）= `depositAmount / actualReceived`，保留 2 位小数
- 原"定金比例 50% 默认"行为不变（不输入任何值时仍按 50% × 实收价）

后续流程（登记定金模态框 / 订单预览 / 打印）继续用 `requiredDeposit` 校验是否已收够，无破坏。

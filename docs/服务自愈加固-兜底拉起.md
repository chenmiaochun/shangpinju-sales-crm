# 服务自愈加固：兜底拉起（2026-09-02）

## 问题

服务会莫名其妙停掉，员工第二天来上班打不开系统。

根因：`scripts/install-autostart.mjs` 注册的计划任务 `ShangPinJuSalesGuard`
触发器是 **ONLOGON（用户登录时）**：

- 电脑重启后**没人登录** → 守护进程不会启动 → 服务一直挂
- 休眠 / 锁屏唤醒 → 守护进程不会重新启动
- 计划任务查询里「下次运行时间 = N/A」就是这个原因

## 加固方案

在常驻守护（登录时启动，负责 30 秒级崩溃自愈）之外，补两个**兜底**计划任务，
两者都调用新增的 `scripts/ensure-services.mjs`（幂等，端口在就直接退出，不留常驻进程）：

| 计划任务 | 触发 | 作用 |
|---|---|---|
| `ShangPinJuSalesGuard-Boot` | 系统启动时（ONSTART，无需用户登录） | 开机就把服务拉起来 |
| `ShangPinJuSalesGuard-Hourly` | 每小时（HOURLY /mo 1） | 每小时整点检查，掉了就补 |

三层保障：

1. **开机** → Boot 任务拉起
2. **登录后** → 常驻 service-guard，30 秒级崩溃自愈
3. **运行中** → 每小时兜底检查（覆盖休眠唤醒、guard 被杀等场景）

## 新增文件

- `scripts/ensure-services.mjs` —— 检查 3001/5173，不通则拉起 `dev.mjs`，
  等待端口就绪（最多 90 秒）后退出；端口都在时直接退出（幂等）
- `scripts/install-watchdog.mjs` —— 注册 / 查看 / 注销这两个兜底计划任务
  - `node scripts/install-watchdog.mjs install | status | uninstall`

## 验收（故障演练）

1. 停掉常驻守护与服务（模拟 guard 被杀 / 未登录场景）
2. 端口 3001、5173 均无监听
3. 运行 `node scripts/ensure-services.mjs`
   → 输出「检测到服务缺失…已拉起 dev.mjs…服务已就绪」
4. 复查：`3001=200`、`5173=200`、局域网 `http://192.168.1.161:5173 = 200`
5. 重新拉起常驻 `service-guard.mjs`，三层保障就位

## 运维命令速查

```bash
# 看计划任务与服务状态
node scripts/install-autostart.mjs status   # 常驻守护（登录时）
node scripts/install-watchdog.mjs  status   # 两个兜底任务

# 手动兜底拉起（幂等，服务在跑时安全无副作用）
node scripts/ensure-services.mjs

# 取消兜底（不动常驻守护）
node scripts/install-watchdog.mjs uninstall
```

## 注意

- `install-autostart.mjs status` 对 ONLOGON 任务会显示「状态异常」，
  因为这类任务的「下次运行时间」是 N/A，属**误报**，任务其实是正常的
- 所有计划任务使用系统 node（`C:\Program Files\nodejs\node.exe`），
  不依赖 WorkBuddy 托管运行时路径，避免被清理后失效
